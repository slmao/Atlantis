# `atlantis.remote/1` — Protocol Reference

**Status: descriptive reference** (Spec 0058 ruling Q8, ADR-0112 D2; Plan
0058 J13). This document describes the protocol **as the code implements
it**:
- `src/remote/src/codec.cpp`, `remote_server.cpp`, `remote_client.cpp`;
- `src/remote/src/session_file.cpp`;
- `src/connection/src/json.cpp`.

**Where they differ, the code is right.** The difference is a
documentation bug, fixed in the PR that finds it.

A change to the protocol's *behaviour* is a different thing. It needs a
Spec and a new ADR superseding
[ADR-0106](../adr/0106-attachable-runtime-transport-and-control.md), and the
version string below changes with it.

**Implementations:**
- **C++:** Atlantis Remote's client and server halves (`src/remote/`).
- **C#:** Atlantis C# SDK (`src/csharp/Atlantis.Gameplay/Remote/`).

**Conformance vectors:** `tests/csharp/conformance/codec_vectors.jsonl`,
generated by the C++ codec and staleness-checked
(`atlantis_csharp_conformance_tests`). Every implementation must decode
each `wire` value and re-encode it to the same bytes.

## 1. Discovery: the session file

A Runtime started with `atlantis_runtime --listen <port>` (`0` means
ephemeral) binds `127.0.0.1` only. Once listening, it writes one JSON
object and a `\n` to its session file:

```json
{"protocol":"atlantis.remote/1","port":51234,"token":"<32 lowercase hex>","pid":4242,"scene":"<asset GUID>"}
```

- **Location:** `--session-file <path>`, else
  `./.atlantis/runtime.session.json` relative to the Runtime's working
  directory.
- **Lifetime:** the file is removed on a clean shutdown.
- **How a client finds it,** in this order:
  - an explicit path (the `atlantis` executable's `--session`);
  - else the `ATLANTIS_SESSION` environment variable, if set and non-empty;
  - else the default path above, relative to the client's working
    directory.
- **Parsing.** A client refuses a file whose `protocol` is not exactly
  `atlantis.remote/1` (`WrongProtocol`). A file is `Malformed` when any of
  these hold:
  - it is not an object;
  - `port` is not an integer in 1–65535;
  - `token` is not a string;
  - `pid` is not an integer up to 2³²−1;
  - `scene` is not a GUID.

## 2. Connection

- **Transport:** TCP to `127.0.0.1:<port>`.
- **The first request must be `hello`.**
  - **Params:** `{"protocol":"atlantis.remote/1","token":"<the session token>"}`.
  - **Success:** the result is `{"protocol":"atlantis.remote/1","scene":"<asset GUID>"}`.
  - **Failure:** the server answers with `WrongProtocol` or `BadToken` and
    closes. Any other method before a successful `hello` gets
    `HelloRequired` and the connection closes. A second `hello` is a
    `BadRequest`.
- **Server side.** Each client gets its own InProcess `RuntimeConnection`
  (Spec 0054): its own subscriptions and its own failure routing by ticket.

## 3. Framing and limits

- **Lines:** each request and each response is one JSON value on one
  line, ended by `\n`. A trailing `\r` before the `\n` is ignored.
- **Line limit:** a line may be at most 1 MiB (1,048,576 bytes, excluding
  the `\n`). A longer request line disconnects the client.
- **Write limit:** the server queues at most 64 MiB of output per client.
  Exceeding it disconnects the client.
- **JSON** (`json.cpp`): RFC 8259, with no comments and no trailing
  commas. Writers emit compact JSON:
  - no whitespace;
  - object members in a fixed order;
  - strings with `"`, `\`, `\b`, `\f`, `\n`, `\r`, `\t` escaped by their
    short forms and other control characters as `\u00XX` (lowercase hex);
  - all other bytes, including non-ASCII UTF-8, written as they are.

  Numbers keep their literal text through a parse.
- **The server polls after every frame** (ADR-0106 D1). Each poll:
  - reads every complete line;
  - answers every request it can answer at once;
  - parks `control.step` until its last frame completes.

## 4. Envelopes

```
request   {"id":<id>,"method":"<name>","params":{…}}      params may be omitted: {}
response  {"id":<id>,"result":<value>}
error     {"id":<id>,"error":{"code":"<name>","message":"<text>"}}
```

- **Ids** are chosen by the client and echoed unchanged. The C++ and C#
  clients use integers from 1. A line that is not a JSON object is
  answered with a `BadRequest` whose `id` is `null`.
- **Order.** Responses to a client come in the order the server produced
  them. A parked `control.step` is answered after its frames, so later
  requests may be answered first. Clients match responses by id.
- **Error codes:**
  - `BadRequest`: not a JSON object, no method, malformed or missing
    params, or an unknown method;
  - `WrongProtocol`, `BadToken`, `HelloRequired`;
  - `NoControl`: a `control.*` method on a server without a control.
- **In-band results.** A method that can be refused by the World or the
  connection answers `{"ok":<value>}` or `{"err":"<error name>"}` inside
  `result`.

## 5. Methods

`<E>` is an entity GUID, `<T>` a TypeId, `<V>` a PropertyValue (§6).

| Method | Params | Result |
|---|---|---|
| `connection.findEntity` | `entity: <E>` | `true`/`false` |
| `connection.listEntities` | — | `[<E>…]`, sorted by GUID |
| `connection.listComponents` | `entity: <E>` | `{"ok":[<T>…]}` (sorted) or `{"err":"<AccessError>"}` |
| `connection.getProperty` | `address: <Address>` | `{"ok":<V>}` or `{"err":"<AccessError>"}` |
| `connection.schema` | — | `[<Type>…]` (§6.7) |
| `connection.submit` | `command: <Command>` | the ticket, a JSON integer |
| `connection.submitTransaction` | `commands: [<Command>…]` | `{"first":<n>,"count":<n>}` |
| `connection.subscribe` | `filter: <Filter>` | the subscription id, a JSON integer |
| `connection.unsubscribe` | `subscription: <n>` | `{"ok":null}` or `{"err":"UnknownSubscription"}` |
| `connection.drainEvents` | `subscription: <n>` | `{"ok":[<Event>…]}` or `{"err":"UnknownSubscription"}` |
| `connection.drainFailures` | — | `[<Failure>…]` |
| `control.status` | — | `{"paused":bool,"frame":<n>,"scene":"<asset GUID>"}` |
| `control.pause` / `control.resume` | — | `null` |
| `control.step` (parked) | `request: {"frames":<n>,"image":null\|"<path>"}` | `{"ok":<FrameReport>}` or `{"err":"<ControlError>"}` |
| `control.diagnostics` | `after: <n>, max: <n>` | `{"entries":[…],"latest":<n>,"dropped":<n>}` |

**Semantics** are `RuntimeConnection`'s and `RuntimeControl`'s (Specs
0052–0055):
- commands apply at the start of the Runtime's next frame, or are held
  while paused;
- a transaction is all or nothing;
- a refused command is reported by `drainFailures` under its ticket.

## 6. Values

### 6.1 Scalars and identifiers

- **Floats:** a float is a JSON number, written as C++ `std::to_chars`
  writes a `float`.
  - **Shortest round trip:** the shorter of fixed and scientific notation,
    fixed on a tie. An integral value in fixed notation is written as its
    exact integer, which is no longer than its shortest digits padded with
    zeros and closer (`5409459712`, not `5409459700`).
  - **Scientific notation:** a lowercase `e`, an explicit sign and at
    least two exponent digits, e.g. `1e+20`, `1e-05`, `-0`, `0.1`,
    `3.4028235e+38`.
  - **Non-finite:** NaN, +∞ and −∞ are the strings `"nan"`, `"inf"` and
    `"-inf"`, so the World's `NonFiniteValue` refusal stays reachable.
  - **Reading:** a reader accepts any JSON number that converts to a
    finite float without range error.
- **`u64` property values** are **decimal strings** (`{"u64":"18446744073709551615"}`).
  Tickets, subscription ids, frame numbers, counts and sequence numbers
  are plain JSON integers.
- **TypeId and FieldId:** `"0x"` followed by exactly 16 lowercase hex
  digits.
- **GUIDs** (entity and asset): lowercase RFC 9562 text,
  `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`; the nil GUID is all zeros.

### 6.2 PropertyValue

A one-member object tagged by the alternative:

```
{"u64":"<decimal>"}  {"f32":<float>}  {"vec3":[<float>,<float>,<float>]}  {"vec4":[…4…]}
{"assetGuid":"<GUID>"}  {"entityGuid":"<GUID>"}  {"enum":<int64>}  {"absent":true}
```

### 6.3 Address, commands and events

```
Address  {"entity":<E>,"component":<T>,"field":<FieldId>}
Command  {"kind":"CreateEntity","entity":<E>}       {"kind":"DestroyEntity","entity":<E>}
         {"kind":"AddComponent","entity":<E>,"component":<T>}
         {"kind":"RemoveComponent","entity":<E>,"component":<T>}
         {"kind":"SetProperty","address":<Address>,"value":<V>}
Event    the same shapes with kinds EntityCreated, EntityDestroyed, ComponentAdded,
         ComponentRemoved, PropertyChanged (the last carries the applied value)
```

### 6.4 Failures, tickets, filters

```
Failure  {"ticket":<n>,"error":"<AccessError>"}
Ticket   {"first":<n>,"count":<n>}       (a transaction; count 0 for an empty one)
Filter   {"kinds":["EntityCreated",…],"entity":<E>|null,"component":<T>|null}
```

- **`kinds`:** listed in the order EntityCreated, EntityDestroyed,
  ComponentAdded, ComponentRemoved, PropertyChanged.
- **Matching:** an event matches when its kind is listed, and its
  entity/component equal the filter's when those are not `null`.

### 6.5 Error names

- **`AccessError`:** `UnknownEntity`, `NilGuid`, `DuplicateGuid`,
  `UnknownComponentType`, `ComponentMissing`, `ComponentAlreadyPresent`,
  `UnknownField`, `FieldNotEditable`, `KindMismatch`, `EnumValueOutOfRange`,
  `NonFiniteValue`, `LightLimitExceeded`, `ActiveCameraProtected`.
- **`ConnectionError`:** `UnknownSubscription`.
- **`ControlError`:** `InvalidRequest`, `NotRendering`, `CaptureFailed`,
  `Stopped`.

### 6.6 Control values

```
FrameReport  {"frame":<n>,"applied":bool,"data":<FrameData>,"image":null|{"path":"…","width":<n>,"height":<n>}}
FrameData    {"directionalLights":[{"direction":[3],"color":[3],"intensity":<float>}…],
              "pointLights":[{"position":[3],"color":[3],"intensity":<float>,"range":<float>}…],
              "view":[16],"projection":[16],"drawItemCount":<n>}
Diagnostics  entries [{"sequence":<n>,"severity":"warning"|"error"|"fatal","message":"…"}]
```

### 6.7 The schema

`connection.schema` returns an array of types:

```
{"id":<T>,"name":"world::Light","kind":"Struct"|"Enum","version":<n>,
 "fields":[{"id":<FieldId>,"name":"intensity","kind":"Primitive"|"Struct"|"Enum",
            "primitive":"UInt64"|"Float32"|"Vec3Float32"|"Vec4Float32"|"AssetGuid"|"EntityGuid",
            "type":<T>,"flags":<n>,"offset":<n>}…],
 "constants":[{"name":"Directional","value":<int64>}…]}
```

- **`flags`:** a bit set — Serializable 1, Editable 2, AssetReference 4,
  EntityReference 8, Optional 16.
- **`primitive`:** meaningful only for `Primitive` fields (other fields
  carry `UInt64`).
- **`type`:** `0x0000000000000000` for primitives.
- **`offset`:** the field's byte offset in World's C++ struct. It is
  transmitted, but it is **internal layout (ADR-0034)**: clients ignore it,
  and the Gameplay SDKs never use it.
