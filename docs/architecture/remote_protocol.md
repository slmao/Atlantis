# `atlantis.remote/1` — Protocol Reference

**Status: descriptive reference** (Spec 0058 ruling Q8, ADR-0112 D2; Plan
0058 J13). This document describes the protocol **as the code implements
it**:
- `src/remote/src/codec.cpp`, `remote_server.cpp`, `remote_client.cpp`;
- `src/remote/src/session_file.cpp`;
- `src/connection/src/json.cpp`.

**Where they differ, the code is right.** The difference is a
documentation bug, fixed in the PR that finds it.

A change to the protocol's *behaviour* is a different thing. It needs a
Spec and a new ADR superseding
[ADR-0106](../adr/0106-attachable-runtime-transport-and-control.md), and the
version string below changes with it.

**Implementations:**
- **C++:** Atlantis Remote's client and server halves (`src/remote/`).
- **C#:** Atlantis C# SDK (`src/csharp/Atlantis.Gameplay/Remote/`).

**Conformance vectors:** `tests/csharp/conformance/codec_vectors.jsonl`,
generated by the C++ codec and staleness-checked
(`atlantis_csharp_conformance_tests`). Every implementation must decode
each `wire` value and re-encode it to the same bytes.

## 1. Discovery: the session file

A Runtime started with `atlantis_runtime --listen <port>` (`0` means
ephemeral) binds `127.0.0.1` only. Once listening, it writes one JSON
object and a `\n` to its session file:

```json
{"protocol":"atlantis.remote/1","port":51234,"token":"<32 lowercase hex>","pid":4242,"scene":"<asset GUID>"}
```

- **`window`** (optional; Spec 0064 / ADR-0126 D3): present only when the
  Runtime was started with `--parent-window <HWND>`. It is the Runtime's
  own child window's `HWND`, as a decimal integer, so the hosting process
  can size and place it. In that mode the file is written once the child
  window exists (after the first frame), not as soon as the port is bound.
- **Location:** `--session-file <path>`, else
  `./.atlantis/runtime.session.json` relative to the Runtime's working
  directory.
- **Lifetime:** the file is removed on a clean shutdown.
- **How a client finds it,** in this order:
  - an explicit path (the `atlantis` executable's `--session`);
  - else the `ATLANTIS_SESSION` environment variable, if set and non-empty;
  - else the default path above, relative to the client's working
    directory.
- **Parsing.** A client refuses a file whose `protocol` is not exactly
  `atlantis.remote/1` (`WrongProtocol`). A file is `Malformed` when any of
  these hold:
  - it is not an object;
  - `port` is not an integer in 1–65535;
  - `token` is not a string;
  - `pid` is not an integer up to 2³²−1;
  - `scene` is not a GUID;
  - `window` is present but is not an integer up to 2⁶⁴−1.

## 2. Connection

- **Transport:** TCP to `127.0.0.1:<port>`.
- **The first request must be `hello`.**
  - **Params:** `{"protocol":"atlantis.remote/1","token":"<the session token>"}`.
  - **Success:** the result is `{"protocol":"atlantis.remote/1","scene":"<asset GUID>"}`.
  - **Failure:** the server answers with `WrongProtocol` or `BadToken` and
    closes. Any other method before a successful `hello` gets
    `HelloRequired` and the connection closes. A second `hello` is a
    `BadRequest`.
- **Server side.** Each client gets its own InProcess `RuntimeConnection`
  (Spec 0054): its own subscriptions and its own failure routing by ticket.

## 3. Framing and limits

- **Lines:** each request and each response is one JSON value on one
  line, ended by `\n`. A trailing `\r` before the `\n` is ignored.
- **Line limit:** a line may be at most 1 MiB (1,048,576 bytes, excluding
  the `\n`). A longer request line disconnects the client.
- **Write limit:** the server queues at most 64 MiB of output per client.
  Exceeding it disconnects the client.
- **JSON** (`json.cpp`): RFC 8259, with no comments and no trailing
  commas. Writers emit compact JSON:
  - no whitespace;
  - object members in a fixed order;
  - strings with `"`, `\`, `\b`, `\f`, `\n`, `\r`, `\t` escaped by their
    short forms and other control characters as `\u00XX` (lowercase hex);
  - all other bytes, including non-ASCII UTF-8, written as they are.

  Numbers keep their literal text through a parse.
- **The server polls after every frame** (ADR-0106 D1). Each poll:
  - reads every complete line;
  - answers every request it can answer at once;
  - parks `control.step` until its last frame completes.

## 4. Envelopes

```
request   {"id":<id>,"method":"<name>","params":{…}}      params may be omitted: {}
response  {"id":<id>,"result":<value>}
error     {"id":<id>,"error":{"code":"<name>","message":"<text>"}}
```

- **Ids** are chosen by the client and echoed unchanged. The C++ and C#
  clients use integers from 1. A line that is not a JSON object is
  answered with a `BadRequest` whose `id` is `null`.
- **Order.** Responses to a client come in the order the server produced
  them. A parked `control.step` is answered after its frames, so later
  requests may be answered first. Clients match responses by id.
- **Error codes:**
  - `BadRequest`: not a JSON object, no method, malformed or missing
    params, or an unknown method;
  - `WrongProtocol`, `BadToken`, `HelloRequired`;
  - `NoControl`: a `control.*` method on a server without a control;
  - `NoAuthoring`: an `authoring.*` method on a Runtime that serves no
    authoring session (Spec 0065), or whose scene's source cannot be found.
- **In-band results.** A method that can be refused by the World or the
  connection answers `{"ok":<value>}` or `{"err":"<error name>"}` inside
  `result`.

## 5. Methods

`<E>` is an entity GUID, `<T>` a TypeId, `<V>` a PropertyValue (§6).

| Method | Params | Result |
|---|---|---|
| `connection.findEntity` | `entity: <E>` | `true`/`false` |
| `connection.listEntities` | — | `[<E>…]`, sorted by GUID |
| `connection.listComponents` | `entity: <E>` | `{"ok":[<T>…]}` (sorted) or `{"err":"<AccessError>"}` |
| `connection.getProperty` | `address: <Address>` | `{"ok":<V>}` or `{"err":"<AccessError>"}` |
| `connection.schema` | — | `[<Type>…]` (§6.7) |
| `connection.submit` | `command: <Command>` | the ticket, a JSON integer |
| `connection.submitTransaction` | `commands: [<Command>…]` | `{"first":<n>,"count":<n>}` |
| `connection.subscribe` | `filter: <Filter>` | the subscription id, a JSON integer |
| `connection.unsubscribe` | `subscription: <n>` | `{"ok":null}` or `{"err":"UnknownSubscription"}` |
| `connection.drainEvents` | `subscription: <n>` | `{"ok":[<Event>…]}` or `{"err":"UnknownSubscription"}` |
| `connection.drainFailures` | — | `[<Failure>…]` |
| `control.status` | — | `{"paused":bool,"frame":<n>,"scene":"<asset GUID>","sceneGeneration":<n>}` |
| `control.pause` / `control.resume` | — | `null` |
| `control.step` (parked) | `request: {"frames":<n>,"image":null\|"<path>","withOverlay":bool}` | `{"ok":<FrameReport>}` or `{"err":"<ControlError>"}` |
| `control.diagnostics` | `after: <n>, max: <n>` | `{"entries":[…],"latest":<n>,"dropped":<n>}` |
| `control.setViewportCamera` | `camera: <ViewportCamera>\|null` | `null` |
| `control.raycast` | `ray: <Ray>` | `{"ok":<RayHit>\|null}` or `{"err":"<ControlError>"}` |
| `control.setViewportOverlay` | `overlay: <ViewportOverlay>\|null` | `{"ok":null}` or `{"err":"InvalidRequest"}` |

**Semantics** are `RuntimeConnection`'s and `RuntimeControl`'s (Specs
0052–0055):
- commands apply at the start of the Runtime's next frame, or are held
  while paused;
- a transaction is all or nothing;
- a refused command is reported by `drainFailures` under its ticket.

**The Viewport camera and the ray-cast** (Spec 0064, ADR-0128):
- `control.setViewportCamera` replaces the camera the Runtime draws from,
  from its next frame; `null` restores the scene's active camera. The
  World's own camera entity is not touched. An in-process editor overlay's
  camera, when it supplies one, takes precedence. A camera the Runtime
  cannot use (for example `nearZ` of zero) is ignored for that frame.
- The camera is owned by the client that set it: when that client
  disconnects, the server clears it (ADR-0128, ruling J2).
- `control.raycast` answers the nearest Renderable the ray hits, in world
  units along a unit `direction`, or `null` for a miss. It answers
  `NoGeometry` when the Runtime keeps no pick geometry: `--listen` keeps it
  unless `--no-pick-geometry` is given.

**The Viewport overlay** (Spec 0066, ADR-0132 D2):
- `control.setViewportOverlay` replaces this client's overlay (§6.6); `null`
  clears it. The Runtime draws, from its next frame, the union of every
  client's overlay: their selections and groups, in the order the clients
  connected.
- `InvalidRequest` when the overlay is not well formed (a non-finite
  float, a colour channel outside [0, 1], a width, size or `pixelsPerUnit`
  not above zero, a nil GUID) or over one client's limits: 256 groups,
  65,536 segments, 65,536 triangles, 16,384 points and 256 selected
  entities, the totals across its groups. Nothing changes then. An
  overlay that is not one in its JSON form fails the request
  (`BadRequest`).
- The overlay is owned by the client that set it: when that client
  disconnects, the server removes it from the union.
- `control.step`'s `withOverlay` (absent is `false`): the captured image
  shows no overlay unless it is `true`, and then only the requesting
  client's own -- never another client's. The overlay the Runtime draws
  to its window is unaffected.

### 5.1 The authoring document (Spec 0065, ADR-0130 D3)

`AuthoringConnection` over the wire: the one authoring document the Runtime
hosts (ADR-0129). `<N>` is a node's entity GUID, `<SA>` a scene address
(§6.8).

| Method | Params | Result |
|---|---|---|
| `authoring.open` | — | `{"ok":null}` or `{"err":"<OpenError>"}` |
| `authoring.document` | — | `<Document>` or `null` before a successful open |
| `authoring.listNodes` | — | `{"ok":[<NodeSummary>…]}` (the node order) or `{"err":"<AuthoringError>"}` |
| `authoring.listComponents` | `node: <N>` | `{"ok":[<T>…]}` (sorted) or `{"err":"<AuthoringError>"}` |
| `authoring.getProperty` | `address: <SA>` | `{"ok":<V>}` or `{"err":"<AuthoringError>"}` |
| `authoring.activeCamera` | — | `{"ok":<N>\|null}` or `{"err":"<AuthoringError>"}` |
| `authoring.schema` | — | `[<Type>…]` (§6.7): the scene component types |
| `authoring.submit` | `command: <AuthoringCommand>` | the ticket, a JSON integer |
| `authoring.submitTransaction` | `commands: [<AuthoringCommand>…]` | `{"first":<n>,"count":<n>}` |
| `authoring.subscribe` | `filter: <AuthoringFilter>` | the subscription id, a JSON integer |
| `authoring.unsubscribe` | `subscription: <n>` | `{"ok":null}` or `{"err":"UnknownSubscription"}` |
| `authoring.drainEvents` | `subscription: <n>` | `{"ok":[<AuthoringEvent>…]}` or `{"err":"UnknownSubscription"}` |
| `authoring.drainFailures` | — | `[<AuthoringFailure>…]` |
| `authoring.apply` | — | `{"ok":null}` or `{"err":"<ApplyError>"}` |
| `authoring.save` | — | `{"ok":null}` or `{"err":"<SaveError>"}` |

**Semantics** are `AuthoringConnection`'s (Spec 0065 R1–R9):
- the session is created by the Runtime at the first `authoring.*` request
  of any client; a client's authoring connection, with its subscriptions and
  failures, lives with its socket connection;
- `authoring.open` (re)reads the Runtime's scene from its source and emits
  `DocumentReopened`; until it has succeeded the queries, `authoring.apply`
  and `authoring.save` answer `NoDocument` (`authoring.document`: `null`), a
  submission is refused `NoDocument` under its ticket, and `authoring.schema`
  and the subscription methods work as usual;
- commands take effect when the request is answered: a transaction is
  applied to a copy of the document, validated (the scene schema, then the
  build's cook of its text) and kept whole or refused whole, its refusal
  reported by `authoring.drainFailures` under its ticket;
- every client's subscriptions see every client's changes;
- `authoring.apply` hands the document to the Runtime, which reloads it at
  its next frame that applies commands — while the Runtime is paused, at the
  next step or on resume, after the held commands (Spec 0065 third
  Correction); subscribers then receive `Applied` with the new
  `control.status` `sceneGeneration` (a failed reload emits nothing and is a
  Runtime diagnostic);
- `authoring.save` writes a hand-authored source atomically; an imported
  scene's save is refused.

## 6. Values

### 6.1 Scalars and identifiers

- **Floats:** a float is a JSON number, written as C++ `std::to_chars`
  writes a `float`.
  - **Shortest round trip:** the shorter of fixed and scientific notation,
    fixed on a tie. An integral value in fixed notation is written as its
    exact integer, which is no longer than its shortest digits padded with
    zeros and closer (`5409459712`, not `5409459700`).
  - **Scientific notation:** a lowercase `e`, an explicit sign and at
    least two exponent digits, e.g. `1e+20`, `1e-05`, `-0`, `0.1`,
    `3.4028235e+38`.
  - **Non-finite:** NaN, +∞ and −∞ are the strings `"nan"`, `"inf"` and
    `"-inf"`, so the World's `NonFiniteValue` refusal stays reachable.
  - **Reading:** a reader accepts any JSON number that converts to a
    finite float without range error.
- **`u64` property values** are **decimal strings** (`{"u64":"18446744073709551615"}`).
  Tickets, subscription ids, frame numbers, counts and sequence numbers
  are plain JSON integers.
- **TypeId and FieldId:** `"0x"` followed by exactly 16 lowercase hex
  digits.
- **GUIDs** (entity and asset): lowercase RFC 9562 text,
  `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`; the nil GUID is all zeros.

### 6.2 PropertyValue

A one-member object tagged by the alternative:

```
{"u64":"<decimal>"}  {"f32":<float>}  {"vec3":[<float>,<float>,<float>]}  {"vec4":[…4…]}
{"assetGuid":"<GUID>"}  {"entityGuid":"<GUID>"}  {"enum":<int64>}  {"absent":true}
```

### 6.3 Address, commands and events

```
Address  {"entity":<E>,"component":<T>,"field":<FieldId>}
Command  {"kind":"CreateEntity","entity":<E>}       {"kind":"DestroyEntity","entity":<E>}
         {"kind":"AddComponent","entity":<E>,"component":<T>}
         {"kind":"RemoveComponent","entity":<E>,"component":<T>}
         {"kind":"SetProperty","address":<Address>,"value":<V>}
Event    the same shapes with kinds EntityCreated, EntityDestroyed, ComponentAdded,
         ComponentRemoved, PropertyChanged (the last carries the applied value)
```

### 6.4 Failures, tickets, filters

```
Failure  {"ticket":<n>,"error":"<AccessError>"}
Ticket   {"first":<n>,"count":<n>}       (a transaction; count 0 for an empty one)
Filter   {"kinds":["EntityCreated",…],"entity":<E>|null,"component":<T>|null}
```

- **`kinds`:** listed in the order EntityCreated, EntityDestroyed,
  ComponentAdded, ComponentRemoved, PropertyChanged.
- **Matching:** an event matches when its kind is listed, and its
  entity/component equal the filter's when those are not `null`.

### 6.5 Error names

- **`AccessError`:** `UnknownEntity`, `NilGuid`, `DuplicateGuid`,
  `UnknownComponentType`, `ComponentMissing`, `ComponentAlreadyPresent`,
  `UnknownField`, `FieldNotEditable`, `KindMismatch`, `EnumValueOutOfRange`,
  `NonFiniteValue`, `LightLimitExceeded`, `ActiveCameraProtected`.
- **`ConnectionError`:** `UnknownSubscription`.
- **`ControlError`:** `InvalidRequest`, `NotRendering`, `CaptureFailed`,
  `Stopped`, `NoGeometry`.

### 6.6 Control values

```
FrameReport  {"frame":<n>,"applied":bool,"data":<FrameData>,"image":null|{"path":"…","width":<n>,"height":<n>}}
FrameData    {"directionalLights":[{"direction":[3],"color":[3],"intensity":<float>}…],
              "pointLights":[{"position":[3],"color":[3],"intensity":<float>,"range":<float>}…],
              "view":[16],"projection":[16],"drawItemCount":<n>}
Diagnostics  entries [{"sequence":<n>,"severity":"warning"|"error"|"fatal","message":"…"}]
ViewportCamera {"worldMatrix":[16],"fovYRadians":<float>,"nearZ":<float>,"farZ":<float>}   (column-major)
Ray          {"origin":[3],"direction":[3]}                                        (world space, unit direction)
RayHit       {"entity":"<E>","distance":<float>}
```

**The Viewport overlay** (Spec 0066, ADR-0132 D1). Its floats are JSON
numbers only (no `"nan"`/`"inf"` text: an overlay's floats are finite).
Every member is required.

```
ViewportOverlay {"selection":["<E>"…],"groups":[<Group>…]}
Group     {"anchor":null|{"position":[3],"pixelsPerUnit":<float>},
           "segments":[{"a":[3],"b":[3],"color":[4],"depth":<Depth>,"width":<float>}…],
           "triangles":[{"a":[3],"b":[3],"c":[3],"color":[4],"depth":<Depth>}…],
           "points":[{"p":[3],"color":[4],"depth":<Depth>,"size":<float>}…]}
Depth     "Tested" | "OnTop"
```

- **`selection`:** the entities the Runtime outlines, from their meshes.
- **A group** is world (`anchor` `null`: its positions are world
  positions) or screen-constant: its positions are offsets from the
  anchor's `position`, one unit drawn as `pixelsPerUnit` pixels at the
  anchor's view depth, from the frame's own camera.
- **`color`:** straight alpha, authored in sRGB, each channel in [0, 1].
- **`width`** (a segment's) and **`size`** (a point's) are in pixels.
- **`depth`:** `Tested` against the scene's depth, or drawn `OnTop` of it.

### 6.7 The schema

`connection.schema` returns an array of types:

```
{"id":<T>,"name":"world::Light","kind":"Struct"|"Enum","version":<n>,
 "fields":[{"id":<FieldId>,"name":"intensity","kind":"Primitive"|"Struct"|"Enum",
            "primitive":"UInt64"|"Float32"|"Vec3Float32"|"Vec4Float32"|"AssetGuid"|"EntityGuid",
            "type":<T>,"flags":<n>,"offset":<n>}…],
 "constants":[{"name":"Directional","value":<int64>}…]}
```

- **`flags`:** a bit set — Serializable 1, Editable 2, AssetReference 4,
  EntityReference 8, Optional 16.
- **`primitive`:** meaningful only for `Primitive` fields (other fields
  carry `UInt64`).
- **`type`:** `0x0000000000000000` for primitives.
- **`offset`:** the field's byte offset in World's C++ struct. It is
  transmitted, but it is **internal layout (ADR-0034)**: clients ignore it,
  and the Gameplay SDKs never use it.

### 6.8 Authoring values (§5.1)

```
SceneAddress      {"node":<N>,"component":<T>,"field":<FieldId>}
AuthoringCommand  {"kind":"SetProperty","address":<SceneAddress>,"value":<V>}
                  {"kind":"CreateNode","node":<N>|null,"position":<n>,"components":[<T>…]}
                  {"kind":"DestroyNode","node":<N>}
                  {"kind":"AddComponent","node":<N>,"component":<T>}
                  {"kind":"RemoveComponent","node":<N>,"component":<T>}
                  {"kind":"SetParent","node":<N>,"parent":<N>|null}
                  {"kind":"SetActiveCamera","camera":<N>|null}
AuthoringEvent    {"kind":"PropertyChanged","address":<SceneAddress>,"value":<V>}
                  {"kind":"NodeCreated","node":<N>,"position":<n>}   {"kind":"NodeDestroyed","node":<N>}
                  {"kind":"ComponentAdded","node":<N>,"component":<T>}
                  {"kind":"ComponentRemoved","node":<N>,"component":<T>}
                  {"kind":"ParentChanged","node":<N>,"parent":<N>|null}
                  {"kind":"ActiveCameraChanged","camera":<N>|null}
                  {"kind":"DocumentReopened","scene":"<asset GUID>"}   {"kind":"Applied","generation":<n>}
AuthoringFilter   {"kinds":["PropertyChanged",…],"node":<N>|null,"component":<T>|null}
AuthoringFailure  {"ticket":<n>,"error":"<AuthoringError>"}
Document          {"scene":"<asset GUID>","provenance":"HandAuthored"|"Imported","source":"<path>","nodeCount":<n>}
NodeSummary       {"node":<N>,"parent":<N>|null}
```

- **`CreateNode`** with a `null` node mints the node's GUID. Its event is
  followed by one `ComponentAdded` per listed component.
- **Filter `kinds`** are listed in the order PropertyChanged, NodeCreated,
  NodeDestroyed, ComponentAdded, ComponentRemoved, ParentChanged,
  ActiveCameraChanged, DocumentReopened, Applied. An event matches when its
  kind is listed and its node and component equal the filter's when those
  are not `null`; `ActiveCameraChanged`, `DocumentReopened` and `Applied`
  carry no node, and only `PropertyChanged`, `ComponentAdded` and
  `ComponentRemoved` carry a component.
- **Error names:**
  - **`AuthoringError`:** `NoDocument`, `UnknownNode`,
    `UnknownComponentType`, `ComponentMissing`, `ComponentAlreadyPresent`,
    `ComponentRequired`, `UnknownField`, `KindMismatch`,
    `EnumValueOutOfRange`, `NodePositionOutOfRange`, `FieldOutOfDomain`,
    `NonEmptyDocument`, `NodeGuidNonNil`, `NodeGuidUnique`, `ParentExists`,
    `ParentAcyclic`, `ActiveCameraExists`, `ActiveCameraHasCamera`,
    `ComponentExclusivity`, `LightRangeMatchesKind`, `MaxDirectionalLights`,
    `MaxPointLights`, `CookRefused`, `NotRepresentableInSource`;
  - **`OpenError`:** `SourceUnreadable`, `SourceParseFailed`,
    `SourceInvalid`;
  - **`SaveError`:** `NoDocument`, `ImportedSceneNotSavable`, `WriteFailed`;
  - **`ApplyError`:** `NoDocument`, `NoSceneSink`, `CookFailed`,
    `DecodeFailed`, `ReloadRefused`.
